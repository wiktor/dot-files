# Second Brain (Knowledge Vault)

My personal knowledge base is an Obsidian vault synced via DriveFS at:
`~/DriveFileStream/Other computers/My Mac/WorkDB/`

Use it as extended memory and context. When working on a topic, check if
relevant notes exist there first — they often contain my reasoning, decisions,
prior research, and meeting context that won't be in code or docs.

Structure:
- **Top-level folders** = active projects/areas (e.g. `Project X onboarding`)
- **`Log/`** = chronological notes, session learnings, audit trail
- **Daily log** = [Google Doc](https://docs.google.com/document/d/<docId>/edit?tab=<tabId>)
  (use only the "this week" tab — read sparingly, it's expensive to fetch)
- **`__Archive/`** = completed or paused work, still useful for historical context
- **Files are markdown** — readable directly with reading a file

Guidelines:
- **Read freely** — browse and reference vault notes whenever they'd add context
- **Write only when asked** — don't modify vault files unless I explicitly ask
- **Cite what you use** — if a vault note influenced your answer, link to it
- **Respect structure** — if creating notes, follow existing naming (`YYYY-MM topic.md`)
- **Suggest distillation** — after a productive session that generated reusable
  knowledge (debugging, research, onboarding), propose a vault note capturing
  the key learnings. Don't write it — just suggest the title and outline.
- **Compound, don't duplicate** — before proposing a new note, check if an
  existing one covers the same topic. Propose merging into it instead.
- **Suggest cleanup** — when browsing the vault, flag stale notes,
  contradictions between notes, or topics that should be merged. Propose fixes.
